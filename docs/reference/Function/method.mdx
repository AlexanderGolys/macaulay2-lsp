# method

**method  -- make a new method function**

**Type:** [FunctionClosure](../Type/FunctionClosure.mdx)

## Description

The code above creates a method function that takes up to four arguments looking up the appropriate method according to the classes of the arguments with inheritance.  To install a method for two arguments (xy) of classes X and Y use code like this:
```
     f(XY) := (xy) -> ...
```
where '...' represents the body of the function you wish to install. The syntax for one or three arguments is analogous.  See [:=](../Method/op_Coredollar_colon_eq.mdx)  for details.In the following example we install a asymmetric method to illustrate the left-associative order of evaluation for a *binary*  method function. By default at most four arguments (in a sequence) can be handled by a method function and the types have to be considered separately when installing methods. In this example we define a method function that treats a sequence as a single argument and we install a method for handling such arguments. Here we define a method whose first argument is to be a type.  It will convert its second argument to that type.In the next example we make a linear function of a single real variable whose coefficients are provided as optional arguments named Slope and Intercept with default value 1.The methods installed for this method function should be written in the form `opts -> args -> (...)` .  The argument `opts`  will be assigned a hash table of type [OptionTable](../Type/OptionTable.mdx)  containing the optional argument names and their current values.  For example in the body of the function the current value for the argument named `b`  can be recovered with `opts#b`  or with `opts.b`  in case `b`  is known to be a global symbol.  Be careful not to change the value of `b`  or the code will stop working; it would be a good idea to protect it.The default [ option table](../Type/OptionTable.mdx)  for `r`  can be recovered with the function [options](../Method/op_Coredollar_options.mdx) .  The options given to [method](../Function/op_Coredollar_method.mdx)  can be recovered with [methodOptions](../Method/methodOptions.mdx) .In the next example we define a method function that leaves option processing to the individual methods.For now one installs a method function for `s`  with no non-optional arguments using [installMethod](../Function/op_Coredollar_installMethod.mdx) :

## Additional Information

- [ Optional inputs](../Instance/using functions with optional inputs.mdx):
- `TypicalValue```a [ type](../Type/op_Coredollar_Type.mdx) default value Thing the type of the value returned by `f` typically. This information is used only to build documentation automatically and is stored in the hash table [typicalValues](../Instance/typicalValues.mdx).
- `Options```a [ list](../Type/op_Coredollar_List.mdx) default value null a list of options `` where `J` is the name of an optional argument for `f` and `v` is its default value. The list of options could be also replaced by the corresponding [OptionTable](../Type/OptionTable.mdx). Specifying `true` here indicates that option handling is done by the individual methods while still allowing dispatching to methods based on types of arguments to be done. The individual methods may have various sets of acceptable option names possibly empty. See [making new functions with optional arguments](../Instance/making new functions with optional arguments.mdx).
- `Binary```a [ Boolean value](../Type/op_Coredollar_Boolean.mdx) default value false whether the method is to be binary: for three arguments or more the result will be computed by calling binary methods installed for `f` with two arguments at a time.
- `Dispatch````...` default value {Thing, Thing, Thing, Thing} the method for getting a list of types from the parameters; the value of this option should be [Thing](../Type/Thing.mdx) or [Type](../Type/op_Coredollar_Type.mdx) to indicate that a sequence should be regarded as a single argument or if the elements of a sequence are to be regarded as separate parameters a list whose elements are [Thing](../Type/Thing.mdx) or [Type](../Type/op_Coredollar_Type.mdx). Parameters corresponding to [Thing](../Type/Thing.mdx) or to a position beyond the end of the list are dispatched according to their [class](../Function/op_Coredollar_class.mdx) whereas parameters corresponding to [Type](../Type/op_Coredollar_Type.mdx) are expected to be types (actually hash tables) and are used directly in the search for methods; see [inheritance](../Instance/inheritance.mdx).
- Outputs:
- `f` a new method function a [ method function](../Type/op_Coredollar_MethodFunction.mdx) a [ method function with a single argument](../Type/MethodFunctionSingle.mdx) an [ associative binary method function](../Type/MethodFunctionBinary.mdx) or a [ method function with options](../Type/op_Coredollar_MethodFunctionWithOptions.mdx)
