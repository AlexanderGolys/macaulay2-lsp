# symmetricAlgebra

**symmetricAlgebra  -- the symmetric algebra of a module**

**Type:** [MethodFunctionWithOptions](../Type/MethodFunctionWithOptions.mdx)

## Description


### Synopsis


- Inputs:
- `M` a [ module](../Type/op_Coredollar_Module.mdx)
- Outputs:
- a [ ring](../Type/Ring.mdx) the symmetric algebra of `M`

Most of the optional arguments for monoids (see [Ring Array](../Instance/Ring Array.mdx)  or [monoid](../Method/monoid.mdx) ) are available here as well as in the following example.  They apply to the variables that correspond to the generators of the module.
### Synopsis


- Inputs:
- `f` a [ matrix](../Type/op_Coredollar_Matrix.mdx)
- Outputs:
- a [ ring map](../Type/op_Coredollar_RingMap.mdx) the map between symmetric algebras induced by `f`


### Synopsis


- Inputs:
- `A` a [ ring](../Type/Ring.mdx) the symmetric algebra of the target of `f` previously computed. Optional.
- `B` a [ ring](../Type/Ring.mdx) the symmetric algebra of the source of `f` previously computed. Optional.
- `f` a [ matrix](../Type/op_Coredollar_Matrix.mdx)
- Outputs:
- a [ ring map](../Type/op_Coredollar_RingMap.mdx) the map between the specified symmetric algebras induced by `f`

This form of functoriality is needed because various options are available when computing symmetric algebras.For a linear map that is an isomorphism and is known to be so e.g. by having had its inverse computed the inverse of the corresponding map between symmetric algebras is precomputed and made available.
