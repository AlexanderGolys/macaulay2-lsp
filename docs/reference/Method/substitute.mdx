# substitute

**substitute  -- substituting values for variables**

**Type:** [MethodFunction](../Type/MethodFunction.mdx)

## Description

A convenient abbreviation for [substitute](../Method/sub.mdx)  is `sub` . This function allows you to substitute values for some variables.  There are three ways to describe the kind of substitution depending on the second argument `v` .
- give specific values for (some of) the variables. An option `` specifies that a generator `x` should be replaced by the ring element `r`. Generators not mentioned will be preserved.
- give a matrix the entries determines the values of each of the variables
- give a ring the effect will be to substitute variables with variables of the same name into this new ring

 The following line substitutes values for a and b and the result is in the same ring `B`  of `F` . Substitute `a`  by `x`  `b`  by `y`  and so on.  The result is a polynomial in the ring `C` . Using a ring as the second argument substitutes variables with the same name. The following produces the polynomial `F`  in the rings `A`  and `D` . If the values of all of the variables are in a different ring then the result will be in that ring. If `f`  is an ideal or a submodule of a free module over `R`  then substitution amounts to substitution in the matrix of generators of `f` .  This is not the same as tensor product! Although we cannot use substitute directly on modules which are not submodules here is a useful idiom for moving a cokernel module to another ring.  One must be careful though: the degrees of the generators might not be the desired ones. Unevaluated expressions (i.e. from [hilbertSeries](../Method/op_Coredollar_hilbertSeries.mdx) ) may also have variables substituted in all of the ways mentioned so far. Of course we can change the ring too:If you plan on using the same substitution over and over it is wise to create a ring map that will perform the same substitution.For example in the first example above we can make a [ ring map](../Type/op_Coredollar_RingMap.mdx)  `G`  and then apply it to `F` .

## Additional Information

- Inputs:
- `f` a [ ring element](../Type/RingElement.mdx) a [ matrix](../Type/op_Coredollar_Matrix.mdx) an [ ideal](../Type/op_Coredollar_Ideal.mdx) a [ module](../Type/op_Coredollar_Module.mdx) a [ vector](../Type/op_Coredollar_Vector.mdx) or an [ expression](../Type/op_Coredollar_Expression.mdx) over a ring `R`
- `v` a [ ring](../Type/Ring.mdx) a [ matrix](../Type/op_Coredollar_Matrix.mdx) an [ option](../Type/Option.mdx) or a [ list](../Type/op_Coredollar_List.mdx) of [ options](../Type/Option.mdx)
- Outputs:
- An object of the same sort as `f` obtained by substituting values for the variables in the ring `R` of `f` using `v`.


### Caveat

 The specified substitution is not checked to see whether the corresponding ring homomorphism is well-defined; this may produce surprising results especially if rational coefficients are converted to integer coefficients.
