# RR

**RR  -- the class of all real numbers**

## Description

 A real number is entered as a sequence of decimal digits with a point.  It is stored internally as an arbitrary precision floating point number using the [MPFR](../Instance/MPFR.mdx)  library. The precision is measured in bits is visible in the ring displayed on the second of each pair of output lines and can be recovered using [precision](../Method/op_Coredollar_precision.mdx) . For real numbers the functions [class](../Function/op_Coredollar_class.mdx)  and [ring](../Method/op_Coredollar_ring.mdx)  yield different results.  That allows numbers of various precisions to be used without creating a new ring for each precision. The precision can be specified on input by appending the letter `p`  and a positive number. An optional exponent (for the power of ten to multiply by) can be specified on input by appending the letter `e`  and a number. Numbers that appear alone on an output line are displayed with all their meaningful digits. (Specifying 100 bits of precision yields about 30 decimal digits of precision.) Numbers displayed inside more complicated objects are printed with the number of digits specified by [printingPrecision](../Instance/printingPrecision.mdx) . The notion of equality tested by [==](../Method/op_Coredollar_eq_eq.mdx)  amounts to equality of the internal binary digits. The notion of (strict) equality tested by [===](../Method/op_Coredollar_eq_eq_eq.mdx)  also takes the precision into account. Perhaps surprisingly the IEEE floating point standard also specifies that every number including 0 has a sign bit and strict equality testing takes it into account as it must do because some arithmetic and transcendental functions take it into account. Use [toExternalString](../Method/op_Coredollar_toExternalString.mdx)  to produce something that when encountered as input will reproduce exactly what you had before. Transcendental constants and functions are available to high precision with [numeric](../Method/op_Coredollar_numeric.mdx) .
